# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Cyclo is a single-module (`:app`) Android app written in Kotlin with Jetpack Compose (package `com.gaebriu.cyclo`, minSdk 33, target/compileSdk 37, AGP 9.x). It is in beta (Cyclo Beta 1.0): the app has the onboarding tutorial (Introduction 0–6), which builds the user's first routine, and then the Feed, Saved routines and Settings screens. The same Introduction 2–5 pages are reused to create and edit routines. Two home-screen widgets (Routine, Wake Time). The UI is implemented to match a Figma design.

## Commands

Use `./gradlew` from Git Bash, or `.\gradlew.bat` from PowerShell:

- Build debug APK: `./gradlew assembleDebug`
- Install on a connected device: `./gradlew installDebug`
- Release build (R8 enabled through the `optimization {}` block in `app/build.gradle.kts`): `./gradlew assembleRelease`
  - Signed with the release key read from `~/.gradle/gradle.properties` (`CYCLO_RELEASE_STORE_FILE`, `_STORE_PASSWORD`, `_KEY_ALIAS`, `_KEY_PASSWORD`; keystore `C:/Users/gabri/.android/cyclo-release.jks`). Never commit the keystore or the passwords; every release must use this same key (losing it means users have to reinstall). Without the properties the APK comes out unsigned.
  - `app/proguard-rules.pro` has `-dontrepackage`: without it R8 moved a class out of `kotlin.sequences` and the release crashed on launch (`IllegalAccessError`). Always open the release APK on a device before publishing.
- Lint: `./gradlew lint`
- Unit tests: `./gradlew testDebugUnitTest`
- Single unit test: `./gradlew testDebugUnitTest --tests "com.gaebriu.cyclo.ExampleUnitTest.addition_isCorrect"`
- Instrumented tests (needs a device or emulator): `./gradlew connectedDebugAndroidTest`

Unit tests cover the bedtime engine, backups, the reminder, time format, version labels and the update checker. UI changes are checked by running the app on a device or emulator. The `Medium_Phone` AVD renders Cyclo only with software GPU: start it with `emulator -avd Medium_Phone -gpu swiftshader_indirect` (frame timings there are not representative; check performance on a real device).

Dependency versions are in `gradle/libs.versions.toml`. Releases bump `versionCode` and `versionName` in `app/build.gradle.kts`, and the commit message is the version name.

**Versions:** `versionName` = the GitHub tag = `<stage>-X.Y.Z` for prereleases (`alpha-0.7.3`, `beta-1.0.0`, `rc-1.0.0`) and `X.Y.Z` for stable releases (`1.0.0`). Shown to the user by `AppVersion.label()`, which drops trailing zero patches but keeps `major.minor`: `beta-1.0.0` → "Beta 1.0" (Settings: "Cyclo Beta 1.0"; update: "Cyclo Beta 1.0 is here"), `1.0.0` → "1.0" ("Cyclo 1.0 is here"), `beta-1.0.2` → "Beta 1.0.2". Never hardcode a version in the UI: the installed one comes from the package, the new one from the release tag. Each GitHub release: tag = versionName, not a draft, mark prereleases as such, one `.apk` asset named `cyclo-<tag>.apk`, signed with the same key, built with that exact versionName (the app checks it after download). Don't create tags or publish releases without explicit permission.

## Architecture

- **Orientation and windows:** the app is portrait only and can't be split or floated (`screenOrientation="portrait"`, `resizeableActivity="false"` on the application and `MainActivity`, no PiP). Android 16+ ignores these on large screens (sw ≥ 600 dp); foldables and tablets are out of scope for now. The widgets are separate: the launcher draws them in any orientation, and they scale to the space they get.
- **Entry point:** `MainActivity` turns on edge-to-edge with dark, transparent system bars and renders `ProvideVisualEffects { CycloApp(viewModel) }`. `CycloApp` draws nothing (just the #010101 background, the same as the splash) until `CycloViewModel.data` has been read, so the app opens straight on the tutorial or the Feed with no loading state. Don't hold the first frame with an `OnPreDrawListener`: combined with the splash exit fade it left the app black until the first touch. `CycloTheme`/`MaterialTheme` exist in `ui/theme/Theme.kt` but are **not** used: the UI is built from Compose foundation primitives and the app's own `Cyclo*` components.
- **Data (`data/`):** `CycloRepository` keeps everything in one Preferences DataStore: the `onboarded` flag, the routines as JSON (org.json; enums stored by name) and today's `DailyLog` (caffeine, sleep factors, mood). `CycloViewModel` exposes `data` (null until read) and `message` (the undo-action bar). Every write goes through `write {}`: if it fails, the bar shows an error with "Try again". Deleting a routine shows "Routine removed" with "Undo". The tutorial's routine and the `onboarded` flag are written in the same `edit {}` at the Introduction 5 Next, so a kill during Introduction 6 neither duplicates nor loses the routine. `Routine.nextWake()` decides what the Feed shows (the first wake within 24 h; "Show just this once" counts from `anchorMillis`, the time it was created, edited or switched on), and `bedtimesFor()` gives the bedtimes (wake − n × 90 min − 15 min, n = 6…1).
- **`ui/CycloApp.kt`** is the root. The Feed/Saved shell (`MainScreen`) is the base layer, and the tutorial or the routine editor is an overlay above it, driven by one `cover` Animatable: the overlay rises/falls like Introduction 1 over 0, and the base recedes (scale, blur, veil) underneath. The Feed's first appearance in a session plays a staggered reveal (`effects/StaggeredReveal.kt`) plus the top glow. A `PredictiveBackHandler` lets the editor follow the finger down on its first step; it is declared after `MainScreen` and before the overlay, so it beats the NavHost and loses to the flow's own handlers.
- **`ui/main/`:** `MainScreen` shows the Feed and Saved routines side by side, driven by ONE continuous position (`page` Animatable, 0 = Feed, 1 = Saved; no NavHost, whose transitions can't follow a finger). The pages, the nav pill, the mini-menu's search slot and the glow gradient all read that position, so swipe, nav-bar tap and predictive back are the same movement. The swipe is detected in the Initial pointer pass but only claimed when no child consumed the event (the vertical scroll, the reorder drag and the mood meter win; the swipe slop is 1.5 × touch slop so the meter claims first); it ignores the system gesture insets and is off while search is open. Release: past half a page or a fling above `PageFlingVelocity` changes page; `CycloSprings.Page` starts with the finger's velocity; rubber band past the ends; a threshold haptic when crossing half. Page state survives via `rememberSaveableStateHolder`. Fixed chrome: the top glow, the edge fades, the mini-menu and the navigation bar (`MainChrome.kt`). `FeedScreen` and `SavedRoutinesScreen` are stateless and get data and callbacks (`MainActions`). Search on Saved routines reuses the name field with another placeholder.
- **Reordering (`components/Reorderable.kt`):** `ReorderableColumn` (long press + drag) is shared by Saved routines (persisted with `reorderRoutines`, off while a search filters the list) and the Feed blocks (caffeine, sleep factors, feeling; `FeedSection`, stored as `feed_order` and exported in backups). The `wake-time-recommendation-group` is NOT part of it and stays fixed at the top. The dragged item only moves in its graphics layer (lift scale 1.04 + shadow, `CycloSprings.Lift`), neighbours slide with FLIP (`CycloSprings.Reflow`, small stagger), positions are computed from measured heights (no stale layout), auto-scroll near the top/bottom, `CycloSprings.Drop` on release, haptics DRAG_START / segment tick per swap / GESTURE_END. After the drop the new order is kept until the data arrives (1.5 s timeout if the write fails). TalkBack gets "Move up/down" custom actions. Spacing between items lives inside each item.
- **Delete / restore a routine (Saved):** the card is drawn into a `GraphicsLayer` that doubles as its snapshot; delete captures it, bursts it into particles (`effects/Shatter.kt`: one Canvas for all particles, gravity, spin, shrink, fade, a wave from the delete button) with the `shatter` haptic, and the routine is removed at once so the cards below move up with FLIP. Undo brings it back with `PoppingIn` (zoom from 90 %, opacity, `CycloSprings.PopIn` overshoot, `popIn` haptic) while the others move down. Animations off: no particles, no zoom.
- **`ui/screens/IntroductionFlow.kt`** runs both the tutorial (`IntroductionMode.Tutorial`, steps 0–6) and the routine editor (`IntroductionMode.Editor`, steps 2–5, X on the first step, purple "Done" instead of Next on the last). It owns the flow state (`step`, wake time, routine name, repeat selection) with `rememberSaveable`, and drives three `Animatable`s:
  - `enter`: Introduction 1 rising over 0, while 0 recedes (scale, blur, dark veil). Tutorial only.
  - `position`: horizontal paging from the first page onward.
  - `progress`: the progress bar.

  The top button, progress bar and Next button are fixed chrome (`IntroductionChrome.kt`); only the pages slide. On Introduction 6 the top button and Next fade out and are disabled, and back is blocked. Each `IntroductionNPage` is stateless and gets state and callbacks from the flow. Back handling is layered: a `BackHandler` for step 1, a `PredictiveBackHandler` that moves `position` along with the gesture for the later steps, a no-op `BackHandler` on Introduction 6, and a final `BackHandler` that closes open overlays first. Declaration order sets the priority, and the last one declared wins. A page is composed only while it is on screen or animating (`derivedStateOf` gates).
- **Letter reveal:** `components/LetterReveal.kt` is the "Hello!" animation of Introduction 0 (letters fade in from blur 9 while the letter spacing closes), shared with the Introduction 6 text.
- **Settings (`ui/settings/SettingsScreen.kt`):** a third overlay on the same `cover` animation (opened by the mini-menu gear, closed by back-b or the back gesture). Stateless: it gets `CycloData` and callbacks from `CycloApp`. Rows: age (inline `tap-to-write-box-age`, 5–100, shake + reject haptic when invalid), chronotype / time to fall asleep / time format (compact `CycloActionMenu`, Componentes 3), Bedtime switch, language (display only), Export / Restore, View on GitHub (`CycloBigSheet` first). Time format: `use_24_hour` in DataStore (absent = system format), exposed through `ui/time/TimeFormat.kt` (`ProvideTimeFormat` / `LocalTimeFormat`), which every displayed time uses. The Introduction 2 wheel stays 24 h. The file pickers and the notification-permission launcher live in `CycloApp` (not in Settings) because the message bar's "Try again" can reopen them after Settings is closed; the ViewModel asks for them through `pickerRequests`.
- **Bedtime engine (`data/BedtimeEngine.kt`):** pure Kotlin, unit-tested. Bedtime = wake − cycles × 90 − estimated time to fall asleep, cycles = max(5, enough for the age minimum). Caffeine, factors, mood and chronotype raise the estimated latency (bedtime earlier, never later) and the wind-down preparation; the planned sleep never shrinks. See "Bedtime model" below and the KDoc for the sources.
- **Reminder (`reminder/`):** `BedtimeReminder` schedules ONE inexact `AlarmManager.setAndAllowWhileIdle` broadcast at the wind-down start of the next routine wake (no exact alarms, no `setAlarmClock`, no alarm-app intents). `BedtimeAlarmReceiver` posts the notification and also handles boot / time / timezone / package-replaced. `CycloSync` (started by `CycloApplication`) watches DataStore with an adaptive debounce and reschedules the reminder and updates the widgets.
- **Widgets (`widget/BedtimeWidgets.kt`, `WidgetCanvas.kt`; Figma Componentes 4):** exactly two, no other sizes, variants or layouts.
  - **Routine Widget** (244:48, 345 × 164; provider `BedtimeWidgetProvider`, `widget_routine.xml`, info `widget_bedtime_info.xml`; class and info names kept from the old widget so widgets already on home screens keep working): name, sun + wake time, calendar + repeat, edit-routine-b (opens the editor through `ActionEdit`) and activate/deactivate-routine-b (`WidgetActionReceiver`). **No delete button** (removed from the design on purpose). Off routines get the Saved card's 63 % veil and toggle-off colours. Pinned from Saved routines and Introduction 5 (`requestPin`), bound to its routine when the launcher confirms (`bedtime_widgets` SharedPreferences); launcher-added or orphaned widgets show the next routine.
  - **Wake Time Widget** (244:107, 345 × 171; `WakeTimeWidgetProvider`, `widget_wake_time.xml`, `widget_wake_time_info.xml`): the Feed's wake-time-container, from the same data and logic (`BedtimeEngine.feedWake` = first wake within 24 h, `feedBedtimes` = `bedtimesFor` with today's latency) and the same icons (`CycloAppIconPaths.bedtime(cycles)`); only the icon colour differs (#FCFCFE in the widget, coloured in the Feed). Pinned from the Feed's wake-time "..." action-menu → "Add as a widget" (`requestPinWakeTime`). Each of the six times is a `ViewFlipper` placed over the card, so a new time rolls in (`anim/widget_time_in/out`). No wake within 24 h: the sun row says "No wake-up coming up" (no Figma for this state yet).
  - **Scaling, never deforming:** the launcher's grid decides the size; the card keeps the Figma proportions. For every size in `OPTION_APPWIDGET_SIZES` (portrait, landscape; fallback min/max options), `scale = min(w/345, h/H)` and the whole card is drawn at that scale into one bitmap (`WidgetCanvas`, in Figma units: Inter, icons, button circles, separator), centred in the cell; buttons and time slots are positioned with `setViewLayoutMargin/Width/Height` in scaled Figma coordinates. Widget text scales with the widget, not with the system font size (the one exception to the text-scaling rule). Sent as size-mapped `RemoteViews(Map<SizeF, RemoteViews>)`. Minimum size 250 × 110 dp (below that the text would be too small).
  - RemoteViews only inflates `@RemoteView` classes: never `Space` or plain `View` in widget layouts. The launcher ignores app fonts, hence the bitmaps. Always full `updateAppWidget` (same layout id → `reapply`, so flippers animate); never `partiallyUpdateAppWidget`. `BedtimeWidgets.updateAll` redraws both providers; `BedtimeReminder.nextRefresh` also wakes when the next wake enters the 24 h window. Picker previews are `widget_*_preview.xml` (system font, Figma sample values).
- **Backup (`data/Backup.kt`):** versioned JSON (`format`, `version`, `exportedAt`, `appVersion`, `data`). `parseBackup` validates the whole file; `CycloRepository.restore` writes it in one `edit {}`.
- **Backdrop (`ui/effects/Backdrop.kt`):** glass surfaces draw what is behind them themselves. A zone records its content with `backdropSource`, declares it with `LocalBackdrop`, and each surface (`cycloCard`, `cycloGlassPill`, `cycloOverlaySurface`, the search box) draws it, clipped and optionally blurred (Figma background blur), before its Luminosity fill. This is what keeps Luminosity correct inside animating (offscreen) layers. A surface must never use a source that contains it. `ProgressiveBlur.kt` does the Feed/Saved/Settings top and bottom bands the same way.
- **Sky colours (`ui/main/TimeOfDay.kt`):** the Feed/Saved top glow and the wake-time card shadow follow the device hour (`skyColorsAt`).
- **Motion engine (`ui/theme/Springs.kt`):** every spring comes from `CycloSprings` presets, described iOS-style by response and damping fraction (Exit, Lift, Press, Enter, Snappy, Drop, Reflow, PopIn, Page, Overlay, Gentle, SheetOpen, SheetClose, Sheet, Bounce). The named specs in `CycloMotion` are these presets with their original values. New animations use the presets, start from the finger's velocity when a gesture ends, and use `motionSpec(...)` / snaps when animations are off. Helpers: `rubberBand`, `projectedEnd`. Rules: one continuous position per gesture-driven element (the finger moves it, springs continue it); no exaggerated bounce; screens don't bounce; things that leave are faster than things that enter.
- **action-menu-big (`components/Overlays.kt` `BottomSheetHost` + `CycloBigSheet` / `CycloDaysSheet`):** every bottom sheet shares one physics: position 0 (open) … 1 (hidden) moved directly by the drag, rubber band upwards, opens with `SheetOpen` (0.42 s, 0.88), closes with `SheetClose` (0.34 s, no bounce), both starting from the finger's velocity; on release it closes if dragged past 30 % of the travel (≈ 80 dp, unless flung back up), if `projectedEnd > 0.5`, or on a fast downward flick (emulator `input swipe` reports 0 velocity, so the distance rule is what closes it there). Opacity only follows the first third of the travel. Animations off: fade. Don't give individual sheets their own springs.
- **Wake-time picker (`components/CycloTimeUnitPicker.kt`, `screens/Introduction2Page.kt`):** one picker component for every box (`label` formats each value). Format follows `LocalTimeFormat` (Settings choice, or the system format while the user hasn't chosen: no first-launch write that could override a later choice): 24 h = hour (00–23) + minutes (Figma 8:146); 12 h = hour (12, 01–11) + minutes + `AM-PM-Slider` (Figma 244:150: three 79 × 47 boxes, ":" in the 45 dp gap, 24 dp before AM/PM, labels only over hour and min). Each box changes only its part; the stored wake time is always 24 h. Used by the tutorial and the routine editor (create and edit), which are the same Introduction 2 page. Displayed times use "AM"/"PM" (never "a.m.").
- **Haptics (`ui/haptics/CycloHaptics.kt`):** one function per moment (button, toggle, picker tick, threshold crossed, drag start, reorder step, drop, confirm, reject, shatter, pop-in). Platform constants first (they respect the system touch-feedback setting); `shatter` and `popIn` use `VibrationEffect` primitives only when supported, with `USAGE_TOUCH` (needs the `VIBRATE` permission).
- **i18n (`ui/i18n/AppLanguage.kt`):** English (`values`) and European Portuguese (`values-pt`, so any Portuguese system locale gets it). The choice is Android's per-app language (`LocaleManager`, persisted by the system, also listed in system settings via `res/xml/locales_config.xml`). `MainActivity` handles `configChanges="locale|layoutDirection"`, so the language switches instantly without recreating the activity; `onConfigurationChanged` redraws the widgets and renames the notification channel (`CycloSync.languageChanged`; `LOCALE_CHANGED` does the same for system changes). Dates and times are formatted with `appLocale()` / `rememberAppLocale()` (the `locale_tag` string of the resources in use), never the system default, so the Feed header ("Segunda-feira, 2 de novembro") and the restore sheet follow the app language. To add a language: a `values-xx` folder with every string (including `locale_tag`), an `AppLanguage` entry and a `locales_config` entry.
- **Updates (`update/`):** `CycloUpdates` checks the public GitHub releases API of `R.string.github_url` (no token) on app start/resume, at most every 6 h, with an ETag cache; it reads `/releases` (not `/latest`, which skips prereleases) and picks the newest non-draft tag newer than the installed `versionName` (`AppVersion`: numbers first, then alpha < beta < rc < final). An installed prerelease accepts any newer version; an installed stable version only accepts stable ones. The `.apk` asset whose name contains the tag wins. The `new-update-group` (Figma 56:252 idle, 244:209 downloading; `ui/settings/UpdateGroup.kt`) sits at the top of Settings; its X hides it for 24 h (`dismissed_at` in SharedPreferences `updates`). Flow: "Download now" streams the `.apk` to `cache/updates` with real progress (the group springs to 126 dp: "Downloading...", the segmented `download-bar` and `cancel-download-b`; no close-b while downloading; cancel stops the stream and deletes the partial file) → the file is checked (`getPackageArchiveInfo`: same package, same version as the tag) → the Android installer opens by itself once (`takeAutoInstall`; `FileProvider`, `REQUEST_INSTALL_PACKAGES`; the first time Android asks to allow Cyclo as a source) → the user confirms in the system UI. If they leave the installer, the group shows "Install update". Every error (network, storage, wrong APK, installer not opening) goes to the undo-action bar with "Try again", which downloads (or opens the installer) again; the group returns to "Download now". A new process clears `cache/updates`. A release without an `.apk` opens its page instead. Requires the repository to be public.
- **First launch after an update:** `CycloData.lastRunVersion` (DataStore `last_run_version`, not exported) differs from the installed `versionCode` and the tutorial is done → `CycloApp` shows Introduction 0 without its buttons (`OverlayUpdated`), and when the "Hello!" ends it slides down to the Feed with its reveal. Fresh installs still get the tutorial. The version is stored right away, so it happens once.
- **`ui/effects/VisualEffects.kt`:** `LocalVisualEffects` exposes `blurEnabled` and `animationsEnabled`. `animationsEnabled` comes from the system animator duration scale. Every animation and blur must respect these flags: with animations off, movements become fades, and with blur off, blurs and Luminosity blends are dropped. Do **not** use `WindowManager.isCrossWindowBlurEnabled` for this: it returns false on many devices (for example Samsung) and used to hide the effects.
- **Design tokens (`ui/theme/`):** `CycloColors`, `CycloDimens`, `CycloMotion` (spring and tween specs, which are proposed values to be tuned by eye) and `Type.kt` (bundled Inter fonts). Figma blur values are stored as-is in `FigmaBlur` and must go through `Density.figmaBlurPx()`, because Figma's blur radius is twice Android's sigma.
- **`ui/routine/RepeatSelection.kt`:** the `RepeatOption` and `Weekday` enums. Selected days are stored as a bitmask (bit 0 = Sunday … bit 6 = Saturday). `rememberRepeatSelection()` also holds the open/close state of the overlays. `IntroductionFlow`, `Introduction4Page` and `RepeatOverlays.kt` read it, and `RepeatOverlays.kt` passes it to the generic `CycloActionMenu` and `CycloDaysSheet` components.
- **Other `ui/` packages:** `components/` (reusable Cyclo widgets, overlays, `Pressable`), `effects/` (glow and inner shadow), `dictation/` (speech-to-text input, which uses the `RECORD_AUDIO` permission and the `RecognitionService` query in the manifest), `haptics/`, `keyboard/` (`KeyboardLift`), `icons/` (`CycloIconPaths` for the intro, `CycloAppIconPaths` for the Feed and Saved routines, both raw Figma SVG paths drawn with `CycloIcon`), and `debug/BlurSelfTest.kt` (a diagnostic screen that is not wired into the app).
- **Baked assets:** `res/drawable-nodpi/fx_spotlight.png` is generated by `tools/bake_spotlight.py` (numpy, Pillow, scipy; run `python3 tools/bake_spotlight.py`). Figma's progressive blur can't be exported, so the image is computed. Change the script's parameters and regenerate rather than editing the PNG.

## Conventions

- **Cyclo's voice:** calm, short, warm, plain; "you" in English and "tu" in pt-PT; no technical words (no "JSON parse", "HTTP"); errors say what happened in one line ("Couldn't export your data" / "Não conseguimos exportar os teus dados") and offer "Try again" when retrying makes sense; success messages have no button. Short enough for one line in its element (check margins at 200 % font size). Figma texts are kept as they are; only inferred texts are rewritten, and new inferred texts are shown to the user before landing when they change existing copy.
- **pt-PT terms:** Early bird = "Madrugador", Night owl = "Coruja noturna", Language = "Idioma" (also "Formato e idioma"), download (noun) = "descarga", ellipsis is "…". English stays as in Figma.
- Code comments and KDoc are in European Portuguese. Keep new comments in the same language and style, and reference the matching Figma element or value when relevant.
- The Kotlin source files start with a UTF-8 BOM. Keep it when editing, and don't re-encode files.
- User-facing strings go in `res/values/strings_introduction.xml` (intro flow) or `strings.xml`, and every new string also goes in `res/values-pt/` (European Portuguese, "tu", Cyclo's calm tone). Don't hardcode them in composables. Format dates and times with `appLocale()`.
- Text must scale with the system font size: no fixed heights around text (use `heightIn(min = …)`), and rows put label and value side by side so they wrap instead of overlapping. Checked at 200 %.
- Accessibility matters here: screens covered by another screen are hidden from TalkBack with `clearAndSetSemantics {}`, and touch targets are at least `CycloDimens.TouchTarget` (48 dp) even when the visible element is smaller.

### 4. Intelligent bedtime reminder (notification, scheduling, recommendations)
Not a fixed-time notification. Base it on the real findings (prefer systematic reviews, meta-analyses, guidelines, consensus statements) of: CDC sleep duration https://www.cdc.gov/sleep/about/index.html and https://pmc.ncbi.nlm.nih.gov/articles/PMC4442216/ · chronotype https://pubmed.ncbi.nlm.nih.gov/33545116/ and https://onlinelibrary.wiley.com/doi/full/10.1002/ctm2.1131 · caffeine https://pubmed.ncbi.nlm.nih.gov/36870101/ and https://doi.org/10.1016/j.smrv.2023.101764 · physical activity https://pubmed.ncbi.nlm.nih.gov/30374942/ and https://pmc.ncbi.nlm.nih.gov/articles/PMC9760070/ · emotions/stress/winding down https://pubmed.ncbi.nlm.nih.gov/40840150/ and https://pmc.ncbi.nlm.nih.gov/articles/PMC7853203/ · light and circadian rhythm https://www.ncbi.nlm.nih.gov/books/NBK620865/
- Inputs: only data Cyclo already collects (age, chronotype, sleep/wake schedule, time to fall asleep, caffeine, exercise/sleep factors, mood, history if any). Never invent or assume missing data.
- **Minimum target: 5 estimated cycles (~90 min each, 7h30) per night**, more if the age recommendation is longer. Include time to fall asleep. 90 min is a planning estimate, not a fixed fact. Use history when available.
- Caffeine, stress, exercise, mood, evening habits move **wind-down timing, reminder timing and preparation time only**; they must NEVER reduce the sleep opportunity below the minimum. If the wake time makes 5 cycles impossible, recommend the earliest realistic bedtime, never fewer cycles.
- Priority: 1 age-appropriate duration, 2 ≥5 cycles, 3 required wake time, 4 chronotype/circadian, 5 caffeine/activities/emotions/stress, 6 wind-down and notification timing.
- Safeguards: never claim 5 cycles guarantees restorative sleep; don't assume exactly 90 min; don't turn emotions into arbitrary extra sleep; separate duration, quality and difficulty falling asleep; adjust gradually (stable recommendations); not medical advice.
- Notification: title and body in Cyclo's style, concise, personalised, explain why now is a good time; respect permission/settings; reschedule when inputs change; no duplicates or stale reminders.

### Implementation notes
- **Routine Widget pinning:** from the Saved routines card button and the Introduction 5 "Add as a widget" button. When editing, Introduction 5 uses the routine's id; for a new routine the predicted id (max + 1, what the repository assigns). If the routine is never saved, the widget falls back to the next routine.
- **One reminder per night:** wakes within 12 h of the last notified wake count as the same night (e.g. Work 07:00 + Gym 08:00 → one notification). Covered by `NextReminderTest`.
- **Notification copy:** worded as a plan, not a promise ("Aim to be in bed by … for a full night before …"). Factor-specific tips come first. Otherwise one of four default tips rotates by night.
- **GitHub URL:** from the git remote: `https://github.com/gaebriu/Cyclo` (`R.string.github_url`).
- **Settings defaults (Figma):** age unset ("Tap to write"), Hummingbird, 15 min, Bedtime ON, time format = system. Time-format menu lists 24-hour first (Componentes 3). Spacing from Figma: row→next section label 24 dp, row→description 15, description→next label 15. Version label: "Cyclo " + `versionLabel()` (= `AppVersion.label()` of the installed versionName: "Cyclo Beta 1.0").
- **Fall-asleep values:** "Under 5 minutes" = 5, "15 minutes" = 15, "30 minutes or more" = 30 in the maths. The Feed's bedtimes (`bedtimesFor`) now use this setting instead of the fixed 15.
- **Bedtime switch:** shown ON only if the stored preference is on AND `POST_NOTIFICATIONS` is granted and app notifications are enabled. Tapping it when off asks for the permission. Denied: switch stays off and the bar shows "Allow notifications to turn this on." Re-checked on every resume. No prompt at launch, so on a fresh install the switch shows off until tapped.
- **"No Android alarms" reading:** Cyclo uses its own inexact `AlarmManager` broadcast only to time its notification. That is not a user-visible alarm: no `setAlarmClock`, no `AlarmClock` intents, no `SCHEDULE_EXACT_ALARM`. The notification may arrive a few minutes late. It isn't sent if the wind-down start has already passed (no catch-up notifications), and a night is never notified twice (`notified_wake`).
- **Bedtime model (alpha-0.7.2, replaces the "factors only move the wind-down" rule):** three times: estimated sleep onset = wake − cycles × 90 (fixed, never shrinks); bedtime = onset − estimated latency; wind-down = bedtime − preparation. Factors raise latency (so bedtime moves EARLIER) and preparation; nothing moves bedtime later. Latency = setting + extras (cap +45), computed in two passes because caffeine and chronotype depend on the bedtime. The Feed's bedtimes now use this latency too (1.2 s debounce, `RollingText`).
  - Caffeine: each "+" = one 107 mg coffee with the tap time (`DailyLog.caffeineTimes`; "−" drops the newest). Doses are combined with a 5 h half-life; clear-time = cutoff(dose), linear through 107 mg → 8.8 h and 217.5 mg → 13.2 h (Gardiner 2023). If the bedtime is before that, latency +10 min per 107 mg left at bedtime (5–30), preparation +10 + the same. Untimed cups (old logs): preparation +5 each (max 20), no latency.
  - Mood "Not great": latency +5, preparation +15. "Bad": +10 and +25.
  - Factors use the time they were marked (`DailyLog.factorTimes`) as the latest time they happened. Exercise < 1 h before bed: +10 / +20; 1–4 h: +0 / +10. Meal < 3 h: +5 / +15; 3–5 h: +0 / +10. Nap < 8 h: +10 / +10, else +5 / +5. No time recorded: preparation only (nap +5 latency).
  - Chronotype preferred sleep times: Early bird 22:00, Hummingbird 23:00, Night owl 00:30. Bedtime before it: latency +1 min per 6 min early (max 20). Night owl: preparation +15 (dim lights). Early bird after its time: preparation +1 min per 3 min late (max 30).
  - No light or screen inputs exist (decision 13), so they are only advice in the tips. Preparation cap 120, 5-min steps. The English notification says bed time and "asleep around"; the pt-PT body only says the bed time and the wake time. Today's log only counts for the coming night. If even going to bed now is too late: "Time for bed" (no fewer cycles).
- **Time format:** 12-hour times always use "AM"/"PM" (`cycloTimeFormatter` in `TimeFormat.kt`), never the locale's "a.m."/"p.m.".
- **Backup:** device-specific state (widget bindings, last notified night) is not exported. Settings missing from an older backup keep their current values; routines and the daily log are always replaced. Unknown enum values are ignored; impossible values (hour 25, age 300, bad date) reject the whole file. Duplicate ids get new ids. Files over 2 MB are rejected. Export writes with mode `"wt"` and deletes the document if the write fails. The picker accepts `application/json`, `application/octet-stream` and `text/plain`.
- **Loading overlay:** `LoadingDataOverlay` is the Introduction 6 animation on the loading-data element (Componentes 80:726): same `BlurredRing`, `LetterRevealState`, timings and curves, in the same order (the veil fades in like the page settling, then letters and ring together). Ring 36.5 dp above the screen centre and text 4.5 dp above the ring centre (Figma). It only leaves after the animation ends (`LoadingDataMinMs` = `MinRestoreMs`, 3.02 s), then text, ring and veil fade out together. The backdrop blur is frozen: the screen below is captured once (`toImageBitmap`) and blurred once, because restoring changes that screen and used to re-blur the whole screen every frame.
- **Feed wake-time card (Beta 1.0):** its "..." opens the `action-menu` (Edit, Add as a widget, Remove); nothing else in the card changes. Its 24 dp shadow is part of the reveal: the reveal layer of that block is widened by `WakeShadowBleed` (an offscreen layer with alpha/blur clips to its bounds, which hid the shadow until the reveal ended).
- **Saved routines delete/Undo (alpha-0.7.3):** replaced by the particle burst and `PoppingIn` (see "Delete / restore a routine" above). `ReturningCards` remembers ids deleted on this screen so only an Undo pops in (new routines and search don't animate).
- **Feed bedtimes:** `RollingText` uses proportional figures (as in Figma; "tnum" pushed the "1"s off-centre under the icon) and `TextAlign.Center`; the leaving text doesn't count for the width, so the row doesn't jump at the end of a roll.
- **Toggles:** the Settings switch now springs (a slight stretch at mid-travel, colour and opacity follow it, and it snaps when animations are off). The routine on/off button, day chips and sleep-factor chips already animate with springs.
- **Tests:** `org.json:json` was added as `testImplementation`, because Android's org.json is only a stub in local tests. `BedtimeEngineTest` checks that the sleep opportunity is always ≥ max(age minimum, 450) + latency across ages, chronotypes, latencies and logs. `BackupTest` covers the round trip, rejections, older and unknown values, and duplicate ids.
- **Lint:** existing errors make `./gradlew lint` fail: `ProgressiveBlur.kt:113` (`RememberReturnType`), the BOM literal in `CycloViewModel` (`ByteOrderMark`) and `CycloHaptics.kt` (`WrongConstant` on the spread primitives array). Left untouched. `resizeableActivity=false` warns that Android 16 ignores it on large screens (expected, see Orientation).
